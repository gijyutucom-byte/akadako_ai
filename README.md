# アプリエ for AkaDako（AI App Maker for AkaDako）

アプリエ for AkaDako は、教育用マイコン「[AkaDako（アカダコ）](https://akadako.com/)」シリーズ（タコラッチ／タコラッチ・ミニ）と連携して動く Web アプリを、生成AIとの対話で作るための支援ツールです。先生方や生徒が思い付いた「センサーで測る」「LEDやモーターを動かす」アイデアを、機種に合った仕様書・依頼文に整理し、ChatGPT、Gemini 等の生成AIへ渡せます。

公開ページ：[アプリエ for AkaDako](https://gijyutu.com/g-soft/akadako_ai/)

「アプリエ」（AI App Maker）を AkaDako 向けに拡張したもので、元のアプリエと同じ 3 つの機能（① アプリを作る、② アプリを動かす、③ アプリを理解する）に、AkaDako 用の機能を加えています。

## 主な機能

### ① アプリを作る

使用する機種、目的、機能、条件、参考資料を整理し、AkaDako 用の仕様書・依頼文を作成します。

- **Lite**：保存機能を使わないシンプルなアプリ向け
- **Plus**：保存するデータや保存方法（HTML保存／GAS保存）も検討するアプリ向け
- **簡単設計**：機能と条件を箇条書きで入力
- **詳細設計**：機能ごとに条件を対応付けて入力

#### AkaDako 向けの機能

- **機種の選択**：最初に「タコラッチ・ミニ（TFW-TM1）」か「タコラッチ（TFW-TR1）」を選びます。選んだ機種で使える命令だけを仕様書に書き、別の機種の命令（例：ミニで温度を測る命令）を使わないよう、AIに指示します。
- **部品の選択**：内蔵センサー、フルカラーLED、外付けのアナログ／デジタル入出力、サーボモーターなど、使いたい部品を選べます。
- **接続・切断の条件**：WebMIDI での接続（クリック操作の中で `AkaDako.connect()` を呼ぶ）、接続中の二重接続の防止、切断時の処理、接続失敗時の確認事項とエラー内容（`err.name`・`err.message`）の表示を、仕様書に含めます。
- **機種と入力内容の食い違いの警告**：入力内容に、選んだ機種にない部品（例：ミニで「温度」「湿度」）が含まれると、警告と代替案を表示します。
- **GAS 保存**：AkaDako は WebMIDI で接続するため、GAS の画面内では動きません。AkaDako を操作する画面は端末で開く HTML とし、記録だけを GAS 経由でスプレッドシートへ送る構成で仕様書を作ります。
- **iPad・Chromebook への配慮**：入力欄の文字サイズ、タップ領域、動作環境（PC・Chromebook は Chrome／Edge、iPad は Scrub など）を仕様書に含めます。

#### ブラウザの機能（任意）

AkaDako と組み合わせて、ブラウザの機能も使えます。

| 機能 | 内容 |
| --- | --- |
| カメラ | 映像の表示、写真撮影、QR 読取など |
| 画像認識 | 既存モデルによる手・姿勢・物の認識（MediaPipe／TensorFlow.js） |
| 音声認識 | 発話の文字起こし、音声操作（Web Speech API） |
| 音声合成 | 読み上げ（SpeechSynthesis） |
| **【学習】手の形** | 生徒が手の形を登録して認識（MediaPipe Hands ＋ KNN） |
| **【学習】物・画像** | 生徒が物や絵を登録して認識（MobileNet ＋ KNN） |
| **【学習】音** | 生徒が手拍子・笛などの音を登録して認識（周波数の特徴 ＋ KNN） |

- 画像・音声認識の機能を選ぶと、動作確認済みのライブラリの読み込み方、カメラ・マイクの許可を先に取る順序、失敗箇所とエラー内容の表示、許可・確認・同意・代替手段の条件を、仕様書に含めます。
- 学習モードでは、ラベルの追加、例の登録と登録数の表示、削除、確からしさの表示、結果の安定化、AkaDako の動作への割り当て、学習データの保存・読み込み（数値とラベル名のみ。画像や音は保存しない）を、仕様書に含めます。登録した映像・音は端末の中だけで処理します。

#### 入力と保存

- 入力例は、AkaDako を使ったシステム（明るさセンサーで LED を光らせる、接続して値を表示する、など）にしています。
- 保存するデータの選択肢は、センサーの値、記録日時、測定回数、LED など出力の状態、しきい値などの設定、気づき・メモです。
- 保存する HTML のファイル名は、アプリの名前です（未入力のときは、生成されたコードの `<title>`、それもなければ「作りたいアプリ」の最初の一文を使います）。
- AI に仕様書を生成する前に、中学生向けの注意事項（動作確認、個人情報、外部への送信と保存、AI の答えを信じすぎない、おかしいときは止めて相談）を表示します。

### ② アプリを動かす

アプリがうまく動かないときに、症状、再現する操作、期待する動作、実際の状況を整理し、AI へ修正を依頼する文章を作成します。機種を選ぶと、機種別の確認事項（接続、同期／非同期の命令、使えない命令など）が依頼文に加わります。

### ③ アプリを理解する

仕様とソースコードをもとに、要件定義書と PlantUML 形式のアクティビティ図を作成するための依頼文を生成します。AI の回答を貼り付けると、要件定義書と図を一度に表示でき、印刷・PDF 保存の際の名前は「アプリ名_要件定義書」になります。

## 仕組み

アプリエ for AkaDako はブラウザ上で動作し、利用者の入力を整理して生成AIに渡すためのプロンプトを作ります。外部 AI への自動送信やコードの自動実行は行いません。

生成AIには、HTML・CSS・JavaScript を一つの HTML ファイルにまとめた Web アプリとして出力するよう促します。作られたアプリは、`https://699.jp/src/js/akadako.js`（AkaDako 用ライブラリ）を読み込みます。外部ライブラリ、保存機能、外部サービス連携を用いる場合は、追加の設定が必要になることがあります。

## 機種ごとの違い

| | タコラッチ・ミニ（TFW-TM1） | タコラッチ（TFW-TR1） |
| --- | --- | --- |
| 内蔵センサー | 明るさ（0〜100）、人感（動きあり／なし） | 距離、明るさ（lx）、温度、湿度、気圧、加速度（傾き） |
| 内蔵の出力 | フルカラーLED×1 | フルカラーLED×3、振動モーター |
| 読み取り方 | 同期関数（`await` を付けない） | 非同期関数（`await` を付ける） |
| 外付け | アナログ入力、デジタル入出力など | アナログ、デジタル、I2C など |

## 使い方

1. 「① アプリを作る」で、使用する機種と部品を選びます。
2. 作りたいアプリ、必要な機能、条件、参考資料を入力します。
3. 仕様書を生成し、コピーして、学校で認められた生成AIに貼り付けます。
4. 作成された HTML ファイルを保存します。
5. PC・Chromebook は Chrome または Edge でファイルを開き、AkaDako を USB で接続して、「AkaDako に接続」で動作を確かめます（iPad は Scrub などで開きます）。
6. うまく動かないときは「② アプリを動かす」で状況を整理し、AI に修正を依頼します。
7. 「③ アプリを理解する」で、仕様・コード・処理の流れを確認します。

## 利用上の注意

- AkaDako への接続には WebMIDI が必要です。AI のプレビュー画面や、WebMIDI に対応しないブラウザでは接続できません。
- AkaDako は、同時に一つのアプリからしか接続できません。Scratch など他のアプリや、他のタブで接続中でないか確認してください。
- 接続時に MIDI ポートが 0 件と表示される場合は、USB ケーブル（充電専用でないか）、USB ポート、OS 側のデバイス認識を確認してください。
- `file://` で開いたページは、開くたびにカメラやマイクの許可を聞かれることがあります。
- 画像認識・学習モードのライブラリとモデルは、ネットワークから読み込みます。学校のフィルタで `cdn.jsdelivr.net` や `storage.googleapis.com` が止められていると、動かないことがあります。
- 端末どうしの通信（複数台の Chromebook を連携させるなど）は、学校のネットワークによって WebRTC が使えないことがあります。この機能は、アプリエ for AkaDako の標準の仕様書には含めていません。
- 音声認識は、ブラウザによって音声が外部のサーバーに送信されます。学校の方針や保護者への説明を確認してから使ってください。
- 学習モードの登録内容は、保存しない限りブラウザを閉じると消えます。

## 生徒に使用させる場合

生徒にいきなり使わせるのではなく、ビジュアルプログラミング等で、順次処理、分岐、繰り返し、変数、イベント、入出力、試行・修正といった基礎を学んだ後に扱うことをおすすめします。

利用前に、自治体、教育委員会、学校が定める生成AI利用ガイドライン、情報セキュリティ規程、端末利用のルールを必ず確認してください。利用できる AI サービス・アカウント、入力してよい情報、成果物の公開範囲、著作権の扱いは、各学校の方針に従います。

完成物だけでなく、課題設定、仕様、試作・改善の過程、処理の仕組みを説明できることを重視します。

## 注意事項

- AI が生成するコードや説明は、必ずしも正確ではありません。内容・動作・安全性を確認してください。
- 氏名、学籍番号、メールアドレス、パスワード、API キーなどの重要な情報を AI に入力しないでください。
- PlantUML 図の表示には、ネットワーク接続と外部サービスが必要になる場合があります。
